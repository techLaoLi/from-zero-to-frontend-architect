### 诊断结论（关键）

1. **不是"表达形式"的问题，是"用户带着什么问题来"的问题。** HTML 语法类文章只有一个人会搜：「div 和 span 有什么区别」。搜的人是"查 API 的人"，不是"跟你走的人"。查完就走，不点赞不评论不关注。CSDN 数据印证：HTML 专栏 11 篇评论数 **0**。
2. **面试题形式已经验证过了，而且有效。** 前端面试专栏篇均 1,418，是 HTML 专栏的 **3 倍**。特别是《如何避雷垃圾公司》8,994 —— 它不是"面试题"，是"帮读者避险"的决策类内容。
3. **涨粉的真实瓶颈是评论。** 全账号 73 篇原创只有 2 条评论。知乎算法里评论数与阅读量强相关（> 点赞 > 收藏）。没有评论 = 没有复访 = 没有关注。
4. **读者身份错配。** HTML 专栏读者是"零基础转行者"，但账号简介是"前阿里技术专家 / 专注前端职业突围"。简介承诺的是职场深度，内容给的是 HTML 语法。读者对不上号，关注动机为零。
5. **专栏 01 的 99 篇规划与"涨粉"目标本身冲突。** 99 篇零基础语法教程，是课程资产（可售卖的体系化课程），不是流量资产。用它做涨粉工具，效率是最低的。

### 给出的方向（待用户确认后再改仓库）

- 专栏 01 保留定位为**搜索型长尾资产**（GEO/AI 引用、百度收录），不指望它涨粉。
- 涨粉主力放在**决策类 / 避坑类**内容，形态可以是「面试官视角」「真实项目复盘」「Postmortem」。
- 每篇正文末尾加**一个明确的互动钩子**（评论区提问并承诺回应），补上评论这个缺口。
- 知乎走"回答"形态而非"专栏文章"形态——知乎回答的流量权重是文章的 5-10 倍。
