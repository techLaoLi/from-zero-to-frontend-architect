- **禁止**「讲清楚 XXX」这类模板句式。
- **搜索友好型**，疑问式优先：`div 和 span 有什么区别？零基础看懂块级与行内元素`、`a 标签怎么写？href 和 target 一次讲清`。
- 硬要求：含读者会搜的核心词；12–24 字；不加序号、书名号；禁用「浅谈 / 深入浅出 / 一文搞懂 / 详解」。
- **不加「HTML与CSS基础第N课—」课次前缀**（2026-11-24 定：课次是发布顺序，不是搜索词，占掉标题最值钱的位置）。

- 文件夹名仍按清单原词，与 H1 分离；主图文字必须与 H1 完全一致。
- 发布到 CSDN 时文章标题填 H1 原文，不另加前缀后缀。

## GEO / SEO 正文结构（2026-11-24 定稿，覆盖 10-26 的固定 5 节）

文章发布在 CSDN，读者一半百度搜、一半问 AI。要求内容能被切成一堆可独立引用的知识块。

**原有「固定 5 节」（基本概述/专业定义/代码示例/知识小结/必须掌握）已于 2026-10-27 改为「按大纲分节」，2026-11-24 再叠加下列 GEO 硬要求。**

1. 开头要有可引用的定义句：H1 之后第一段就是核心概念的完整定义，单独成段、加粗。
2. 小标题含核心词。**禁止**「简单示例 / 标签介绍（概念和特征）/ 要点总结」这类每篇都一样的模板句。
3. 定义、示例、代码分块。代码块前后各一句交代这段代码证明什么。
4. 关键概念自包含：不写「后面会讲」，本篇就要给一句够用的结论。
5. 术语前后一致：一个概念只允许一套说法，写完通读一遍。
6. 结尾收束：先给本文结论（3–5 条），再写 `> 下一篇：...`。
7. 对比和术语用表格，表头写核心词，**不留空**。
8. 不为 AI 牺牲可读性：句子还是人话，代码必须能跑。

落点：`AGENTS.md`「GEO 与 SEO 结构（硬要求）」8 条 + 「大纲条目怎么写（GEO 要求）」；`README.md` 单篇文章模板。
