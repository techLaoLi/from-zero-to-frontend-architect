# AI 改代码改坏了，常见的三种翻车方式

**AI 改代码翻车，指的是模型在执行改动时因上下文不足，把变更做成「看起来完成、实际上扩大风险」的结果：范围漂移、依赖猜错、重复实现，是其中最常见的三条路径。**

上一篇谈的是流程选择。流程选对了，仍可能翻车——因为 Agent 改仓库时，缺的往往不是语法，而是你没喂够的事实。本文只拆这三种高频翻车，并收束到同一个根因。

## 翻车一：顺手把改动范围扩大

第一类翻车的表面症状是：你要修一个点，diff 里多出一串「顺手优化」。

模型很擅长发现「附近还有点别扭」：命名不统一、函数能抽一层、相邻组件写法旧了。在没有硬边界时，它会把这些观察当成任务的一部分，一并改掉。单看每一处都像改进；合在一起，审查面和回归面同时爆炸。

| 你要的 | 模型常做成的 | 代价 |
|---|---|---|
| 改登录失败文案 | 顺手重构成新的错误处理层 | 无关模块被卷入回归 |
| 修一个 prop 类型 | 把整个组件文件「整理」一遍 | review 分不清哪些是必要变更 |
| 补一条接口字段 | 把调用方风格统一成另一种写法 | 冲突多、回滚难 |

这类翻车的关键不在「模型爱重构」，而在「任务没有负向约束」。你只说了要做什么，没说不能碰什么，模型就会用自己的完成欲填空。

可执行的防法很窄：改动前写死允许触及的文件或目录；验收时先看 diff 文件列表，范围不对就拒收，不要先陷入逐行争论。

## 翻车二：猜错依赖版本和 API 签名

第二类翻车发生在模型和仓库真实依赖脱节时。

模型的训练分布里有很多「常见写法」。你仓库里的 React、路由库、请求封装、内部 SDK，版本和签名未必等于它记得的那一版。上下文里如果没有 `package.json`、类型定义、既有调用点，它就会生成「在别处成立、在这里编译不过或运行时报错」的代码。

| 缺失的上下文 | 典型猜错 | 你看到的现象 |
|---|---|---|
| 依赖版本 | 用了已删除或尚未引入的 API | 类型报错、构建失败 |
| 本地封装 | 直接调底层库，绕过团队封装 | 鉴权、日志、错误码全丢 |
| 既有调用示例 | 参数顺序、可选字段、返回结构不对 | 运行时静默异常或页面空白 |

这类错误有时会被闭环修掉：跑一下类型检查，模型根据报错改一轮。但更危险的是「能编译、行为错」：签名碰巧兼容，语义已经偏了。自动化过了，业务没过。

防法同样指向上下文，而不是指向「换更强模型」：先让它读真实依赖和同仓库的成功调用；禁止在未见类型定义时发明封装；验收必须覆盖行为，不只覆盖构建。

## 翻车三：造出重复实现

第三类翻车更隐蔽：功能对了，但仓库里多出一套平行实现。

你让它加「下载 CSV」。仓库里其实已有导出工具、权限校验和文件命名约定。模型没读到，就在新文件里写了一套「能用的导出」。表面上任务完成；实际上团队多了一条要维护的岔路——下次改导出规则，有人改旧的，有人改新的，行为开始分叉。

| 已有资产 | 模型不知道时会做什么 | 长期后果 |
|---|---|---|
| 工具函数 / hooks | 再写一个几乎同名的工具 | 修复要打两份补丁 |
| 设计令牌 / 组件库 | 用裸 CSS 或第三方组件顶上 | UI 与规范漂移 |
| 错误码与埋点约定 | 自创一套日志和提示文案 | 排障和数据分析断裂 |

重复实现之所以难查，是因为它常常「通过验收」：新路径自己能跑。验收如果只验证新需求，不验证「是否复用既有能力」，这类债会安静地堆积。

防法是检索优先于生成：先搜仓库里有没有同类能力；有就扩展，没有再新建；PR 描述里写明复用了哪条旧路径，方便审查对上号。

## 三种翻车都指向同一个根因：上下文缺失

三种路径的表现不同，根因同一：模型在关键事实上是盲的，却必须继续推进任务。

| 翻车 | 缺的是哪类上下文 | 模型用什么填空 |
|---|---|---|
| 范围扩大 | 负向约束（不能碰什么） | 完成欲和「顺便改进」 |
| 版本与签名猜错 | 真实依赖、类型、既有调用 | 训练分布里的常见 API |
| 重复实现 | 仓库已有能力与约定 | 从零生成一套能跑的新路径 |

所以「换一个更听话的模型」只能缓解，不能根治。上下文缺失时，任何会规划、会改文件的 Agent，都会用某种默认假设把洞补上。默认假设一旦和本地事实冲突，翻车就成形。

人在这条链上的职责也很清楚：不是替模型写每一行，而是在它动手前补齐边界与事实，在它交卷后用范围审查和行为验收抓住填空痕迹。

## 要点总结：翻车可以追到源头

1. 顺手扩大改动范围：缺负向约束，模型把「附近的改进」当成任务。
2. 猜错依赖版本和 API：缺真实依赖与调用示例，模型用训练记忆填空。
3. 造出重复实现：缺对既有能力的检索，新路径通过验收却埋下分叉。
4. 三条路径的根因都是上下文缺失；边界在这里——先补事实和约束，再谈生成质量。
