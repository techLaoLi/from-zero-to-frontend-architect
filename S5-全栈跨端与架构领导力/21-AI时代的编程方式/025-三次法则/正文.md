# 同一个问题让 AI 试三次还不行，该怎么办

**三次法则是 AI 编程里的叫停规则：同一问题连续试三次仍不过关，就停止继续喂 token，改由人接手查规格、边界和验收，而不是换模型再赌一轮。**

本文只回答一件事：什么时候该让 Agent 停下。并行怎么拆、团队规范怎么写，留给后面几篇。

## 三次法则的判断依据

三次不是玄学，是成本曲线的拐点。

前两次失败，往往还能用「上下文不够、命令跑错、验收漏了一条」解释。第三次还失败，继续试的边际收益通常已经低于人读一遍规格的成本。判断依据按这张表收口：

| 轮次 | 典型信号 | 该怎么做 |
|---|---|---|
| 第 1 次 | 缺文件、命令写错、测试未跑 | 补上下文，再跑一轮 |
| 第 2 次 | 修了 A 坏了 B，或同一报错换皮出现 | 收紧任务边界，明确非目标 |
| 第 3 次 | 仍在同一验收点打转，或改动面越扩越大 | 叫停；人接手 |

「同一问题」要按验收点计，不按对话条数计。换措辞再问一遍、换一个模型再生成一遍，都算同一轮失败的延续，不重置计数。

可当场检查：这个 Agent 会话里，同一个失败断言或同一条规格条款，是否已经连续撞了三次？是，就停。

## 卡住通常是规格问题，不是模型问题

第三次还过不了，优先怀疑规格，不要优先怀疑模型智商。

常见卡点几乎都能映射回规格缺口：

| 卡点表现 | 更可能缺的是什么 |
|---|---|
| 反复改同一文件仍过不了验收 | 验收标准不可判定，或互相矛盾 |
| 每次「修好」都带出新范围 | 非目标和改动边界没写死 |
| 模型在两个方案间来回横跳 | 设计取舍没锁，选型仍开放 |
| 测试绿了但行为不对 | 测试本身在验证错的东西 |

模型在规格模糊时只能用默认假设填空。填空三次还对不上，说明假设空间太大，继续生成只会在错误假设上堆 diff。

人接手时先做三件事，而不是先换模型：重读目标与非目标、把验收改成可执行检查、把这次失败记进规格或规则文件。模型换了，模糊规格还在，失败模式通常不变。

## 人的时间比 token 贵

token 便宜，会制造「再试一次」的幻觉。账要按人的时间算。

| 成本项 | 继续让 AI 试 | 人接手 |
|---|---|---|
| 直接花费 | token 费，通常很低 | 高级工程师的专注时间 |
| 隐藏花费 | 上下文被污染、diff 膨胀、审查变难 | 一次性读懂失败根因 |
| 决策质量 | 容易用「再生成」逃避定边界 | 逼出规格缺口和真实取舍 |

三次之后还往下堆，常见结果不是更接近正确，而是仓库里留下三套半成品。人后来要付的账，是读懂并清掉这些半成品的时间——往往比一开始接手更贵。

决策规则可以写进团队约定：Agent 在同一验收点失败三次，必须输出「卡住原因假设 + 已尝试步骤 + 建议人查的规格条款」，然后停。没有这份交接，接手成本会再涨一截。

## 要点总结：知道什么时候该接手

1. 三次法则按同一验收点连续失败计数；第三次仍不过，就叫停。
2. 卡住时先查规格、边界和验收，不先怪模型和工具。
3. 人的时间比 token 贵；再试一次的便宜，常被后面的清理和审查抵消。
4. 接手标准是：能指出规格哪里不可判定，并把它改到可执行。
