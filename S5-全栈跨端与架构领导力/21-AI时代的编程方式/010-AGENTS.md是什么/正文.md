# AGENTS.md 是什么？给 AI 看的项目说明书

**`AGENTS.md` 是放在仓库里、写给 AI Agent 读的项目说明书：用一份稳定文件提供项目上下文、常用命令、目录结构、代码风格、改动边界和真实示例，让每次新会话都能快速对齐，而不依赖聊天记录里的临时说明。**

规格和任务解决「这一次做什么」。`AGENTS.md` 解决「在这个仓库里默认怎么做」。它是跨会话的持久上下文，不是又一份给人看的 README 副本。

## AGENTS.md 的定义：仓库级的持久上下文

`AGENTS.md` 的主语是仓库约定，不是某个需求。

对话上下文会丢：换会话、换人、换工具，上周叮嘱过的「别动 `legacy/`」就蒸发了。落进仓库文件的约定不会蒸发——前提是你真的维护它。

它和 README、设计文档的分工不同：

| 文件 | 主要读者 | 主要回答 |
|---|---|---|
| `README.md` | 人 | 项目是什么、怎么跑起来 |
| 规格 / 设计文档 | 人 + AI | 这一次要什么、选哪条路 |
| `AGENTS.md` | AI（人也读） | 在这个仓库里默认遵守什么 |

「持久」有两层意思：一是跨会话还在；二是变更走评审，不能靠嘴改。Agent 每次开工先读它，等于入职培训压缩成一页纸。

没有 `AGENTS.md`，你就得在每个任务提示里重复背景。重复的内容一走样，模型就按走样的版本执行。

## 放在哪里，什么时候写

默认放在仓库根目录：`AGENTS.md`。这是 Agent 工具最常约定的发现位置。

| 场景 | 做法 |
|---|---|
| 单仓单项目 | 根目录一份即可 |
| monorepo | 根目录写总规则；子包可放更短的补充，避免互相打架 |
| 新仓库 | 在能跑通最小命令后就写，不要等「以后规范了再补」 |
| 已有仓库 | 先写最高频踩坑的边界和命令，再逐步补全 |

什么时候写：不是文档写完了才开始用 AI，而是准备让 Agent 改这个仓库时就写。越早写，越少在对话里重复；越晚写，错误约定越容易先沉淀进代码。

什么时候改：目录结构调整、常用命令变更、新的硬边界出现时。`AGENTS.md` 过期，危害和过期规格同类——模型会基于谎言干活。

不要把它写成第二份需求文档。需求会变；`AGENTS.md` 只收「长期有效的仓库事实」。

## 六块内容：项目上下文、命令、目录结构、代码风格、边界、真实示例

一份够用的 `AGENTS.md`，通常就这六块。多了会稀释，少了会留下默认假设。

| 块 | 写什么 | 示例方向 |
|---|---|---|
| 项目上下文 | 做什么、技术栈、运行前提 | 「React + Vite 管理端；Node 20」 |
| 命令 | 安装、开发、测试、lint、类型检查 | 给出可复制命令，不写「按惯例」 |
| 目录结构 | 关键目录职责 | `src/features/*` 按业务切，不按技术层切 |
| 代码风格 | 可判定的约定 | 「用函数组件；状态优先用现有 store」 |
| 边界 | 禁区和必须请示的操作 | 「禁止改 `legacy/`；禁止新增状态库」 |
| 真实示例 | 一段符合约定的短代码或改动范例 | 比形容词有效十倍 |

六块里，**命令**和**边界**优先级最高。命令决定 Agent 能不能自我检查；边界决定它敢不敢乱走。代码风格尽量指向已有 lint/format 配置，文件里只写机器管不到、但人又在乎的那几条。

真实示例不是装饰。写「避免大组件」不如贴一个「页面容器 + 展示组件」的最小对照。模型对示范的服从，通常强过对口号的服从。

## 和 CLAUDE.md 的分工

实践里常见两份文件并存：`AGENTS.md` 与 `CLAUDE.md`（或其他工具专属规则文件）。它们不该各写一套互相矛盾的规矩。

| 文件 | 建议职责 |
|---|---|
| `AGENTS.md` | 工具无关的仓库说明书：上下文、命令、结构、边界、示例 |
| `CLAUDE.md` 等专属文件 | 某工具的补充：模型偏好、该工具的钩子/权限、仅该环境生效的说明 |

分工原则：

1. **通用约定只维护一份**，放在 `AGENTS.md`。
2. 工具专属文件只写「这个工具额外需要知道的」，或显式指向 `AGENTS.md`。
3. 发生冲突时，以仓库通用约定为准，并删掉专属文件里的重复段落。

不要为每个工具复制粘贴一整份说明书。复制一次，就埋下一份必然过期的副本。

## 要点总结：写给 AI 的入职文档

1. `AGENTS.md` 是仓库级持久上下文，用来跨会话对齐默认约定，不是 README 的副本。
2. 默认放根目录；准备让 Agent 改仓库时就写，结构或命令变了就改。
3. 六块内容：项目上下文、命令、目录结构、代码风格、边界、真实示例；命令和边界最优先。
4. 与 `CLAUDE.md` 等专属文件分工：通用约定一份维护，专属文件只留增量。
5. 边界在这里：它是写给 AI 的入职文档——短、可执行、可评审。
