# 代码产量不再稀缺以后，什么变稀缺了

**代码产量不再稀缺，指的是：生成可运行代码的边际成本大幅下降之后，团队真正缺的不再是「能写出多少行」，而是判断、上下文、品味和责任这四样不可批量复制的能力。**

上一篇划清了 AI 编程和补全的边界。边界一变，稀缺性也跟着变。本文只回答一件事：写代码变便宜之后，瓶颈移到了哪里，以及为什么「写得快」不等于「交得出去」。

## 写代码的成本下降之后，瓶颈移到了哪

瓶颈永远卡在最贵、最慢的那一环。

过去最贵的是「把想法变成可运行的代码」。人要记 API、查文档、敲实现、修编译错误。这一环耗时长，所以团队优化的是手速、熟练度和代码模板。AI 编程把这一环压下去了：同一段业务逻辑，从「想半天写一天」变成「说清楚半小时出一版」。

成本结构一变，瓶颈就换位置。任务不再卡在「能不能写出来」，而卡在这几处：

| 环节 | 过去为什么贵 | 现在为什么贵 |
|---|---|---|
| 定目标 | 目标糊一点，人会自己补全意图 | 目标糊一点，模型用默认假设填空，改动面失控 |
| 给上下文 | 人脑子里装着仓库习惯 | 模型看不到习惯，只能吃你喂的文件和规则 |
| 验收结果 | 产出慢，审得过来 | 产出快，diff 变大，人审不过来 |
| 担责任 | 写的人天然对结果负责 | 模型不背锅，责任必须显式落在人身上 |

一句话：代码从稀缺资源变成近乎可复制的中间产物。稀缺转移到「决定写什么、怎么验、谁兜底」这一侧。

## 变稀缺的四样东西：判断、上下文、品味、责任

四样东西里，没有一样能靠多开几个 Agent 自动补齐。

| 稀缺物 | 它解决什么问题 | 缺了会怎样 |
|---|---|---|
| 判断 | 这件事该不该做、做到哪一层、用什么方案 | 模型把所有可选路径都实现一遍，仓库变胖 |
| 上下文 | 仓库约定、历史坑、上下游约束 | 模型用「看起来合理」的通用写法覆盖本地习惯 |
| 品味 | 什么叫够好、什么叫过度设计 | 生成代码能跑，但读起来像拼盘，后续难改 |
| 责任 | 谁对线上结果签字 | 出了问题互相指「是 AI 写的」，没有人能叫停 |

**判断。** 判断不是「选哪个库更好看」，而是「这个需求要不要进主路径」「边界条件写到哪一层算够」。模型擅长在给定目标下找实现；目标本身对不对，它不会替你承担。

**上下文。** 上下文是仓库里那套没写全的约定：错误怎么抛、状态放哪一层、哪些文件动不得。人缺上下文会去问同事；模型缺上下文会直接猜，猜错了还写得很自信。

**品味。** 品味看起来主观，其实是长期代价的压缩表达：命名稳不稳、抽象有没有提前、测试保的是行为还是实现细节。产量上来之后，没有品味的代码会以更快的速度堆积。

**责任。** 责任是稀缺里最硬的那一项。AI 可以提议、可以执行、可以修一轮报错；它不能在事故复盘里签字。谁有权合并、谁有权回滚、谁对用户影响负责——这些角色必须是人。

四样稀缺物的共同点：它们都是「在不确定下做取舍」的能力，不是「在确定下生成符号」的能力。

## 产出速度和交付速度不是一回事

产出速度量的是「多快写出一版代码」；交付速度量的是「多快把可验收的变更安全合进主线」。两者经常反向。

| 指标 | 在量什么 | 常见错觉 |
|---|---|---|
| 产出速度 | 从提问到出现 diff 的时间 | 以为 diff 出现就等于接近上线 |
| 交付速度 | 从需求到通过验收并合入的时间 | 忽略审查、回归、回滚成本 |

AI 最容易拉高的是产出速度。一次任务改二十个文件、补一堆测试文件、顺手重构一眼看着别扭的模块——屏幕上很热闹，交付反而变慢：人审不完，CI 红一片，回滚面变大。

真正拉开差距的团队，不是谁生成得更快，而是谁把「可交付」的门槛写清楚：

- 改动边界有没有锁死
- 验收条件能不能自动跑
- 人审的重点是不是只剩判断题，而不是逐行找笔误

没有这些，产出速度只是在更快地制造待审库存。待审库存一堆，交付速度就会掉下去。

## 要点总结：稀缺的是判断力

1. 写代码的成本下降后，瓶颈从「实现」移到定目标、给上下文、验收和担责。
2. 变稀缺的是判断、上下文、品味、责任——四样都不能靠多开 Agent 自动复制。
3. 产出速度不等于交付速度；生成得快、审不过来、合不进去，整体仍然慢。
4. 边界在这里：代码不再稀缺，稀缺的是在不确定下做判断并为此负责的能力。
