# AI 时代还要培养初级工程师吗

**AI 时代仍要培养初级工程师，但入门训练要从「亲手写完所有样板代码」转向「会定验收、会审 diff、会调规格与约束」；任务形态变了，成长链条不能断。**

本文只谈培养路径怎么改。团队规范写哪几条、效率怎么度量，留给后文。

## 初级任务变少了，学习路径怎么办

过去初级工程师靠大量可独立完成的小任务练手：改文案、接简单接口、补表单校验。这类任务正被 Agent 快速吃掉，学习路径若仍绑在「分配足够多的手写小单」上，会同时缺练习场和贡献感。

路径要换底座，不换目标。目标仍是：能独立判断对错、能在约束内交付、能对结果负责。底座从「产出行数」换成「在 AI 辅助下完成可验收闭环」。

| 旧路径依赖 | 新路径依赖 | 为什么要换 |
|---|---|---|
| 大量手写样板 | 读规格、改规格、拆任务 | 样板生成已便宜 |
| 独立小功能从头写 | 在已有 diff 上补边界与测试 | 真实工作变成审与收 |
| 靠时间堆熟练度 | 靠复盘失败轮次堆判断力 | 失败信息密度更高 |

不要用「没初级活了」当停止培养的理由。缺的是旧形态的任务，不是成长本身。组织要主动设计新的练习单：给规格草稿、给半成品 PR、给失败的 Agent 会话，让初级在真实约束里做决策。

## 改成评审和调优：新的入门训练

新的入门训练围着四件事转：读 diff、提审查意见、补测试、收紧提示与规则。

| 训练项 | 初级做什么 | 验收他学会了没有 |
|---|---|---|
| 评审 | 按架构一致、安全、可维护、约定四关写意见 | 能指出「功能对但仍不合格」的点 |
| 调优规格 | 把模糊需求改成可判定条款 | 改完后 Agent 成功率明显上升 |
| 补测试 | 为 AI 生成代码补关键路径与回归 | 测试能抓住真实缺陷，不只是绿 |
| 叫停与接手 | 识别三次法则触发点并写交接 | 知道何时停模型、问什么问题 |

训练设计上，初级不该被当成「便宜的人工补全」。让他只负责点同意合并，成长为零；让他只负责从零手写被 Agent 十分钟能完成的页面，成长也很窄。有效安排是：Agent 出第一版，初级出审查与修正，高年级工程师抽查他的判断，而不是替他点合并。

可当场检查：这个人最近两周，是否独立否决过至少一次「能跑但不该合」的 AI 变更？说得出否决依据，才算训练在生效。

## 理解成本成了新的瓶颈

代码生成变快之后，瓶颈移到理解：读得懂吗、讲得清吗、改得动吗。

| 表面速度 | 真实风险 |
|---|---|
| PR 很快开来 | 作者说不清为什么这样实现 |
| 测试是绿的 | 没人理解失败时该查哪一层 |
| 功能演示通过 | 边界情况依赖模型的隐含假设 |

培养初级时，要把「理解成本」写成显式要求：合并前能用自己的话复述改动意图、数据流和回滚方式。复述不了，就还不能算他的交付——哪怕 diff 是 AI 写的。

这对高年级也是约束：派给初级的 AI 任务，复杂度必须落在他审得动的范围内。审不动的大规模生成，只会制造虚假产能和危险合并。

## 要点总结：任务变了，成长没断

1. 初级手写小单变少，不等于停止培养；换的是练习形态。
2. 新入门训练以评审、调规格、补测试、会叫停为主。
3. 理解成本是新瓶颈；复述不清的变更不算初级的有效交付。
4. 组织要设计半成品与失败会话当教材，而不是空想「还会有很多简单票」。
