# AI 编程是什么？和普通代码补全的三个区别

**AI 编程是一种用 Agent 自主完成软件任务的工作方式：人给出目标和约束，模型拆解步骤、读写文件、调用命令、根据结果迭代，直到任务被验收或明确失败。**

它和编辑器里的代码补全不是同一件事。补全帮你把下一行写完；AI 编程是让模型去执行一个完整任务。本文先把这个边界划清，后面再谈规格、上下文和验收。

## AI 编程是什么：从补全一行到自主执行一个任务

AI 编程的主语是任务，不是光标。

补全在你敲到一半时猜下一个 token：函数名、参数、下一行。你仍然握着方向盘，模型只负责踩油门的那半秒。AI 编程反过来：你先说清「要做成什么、不能碰什么、怎样算过关」，模型自己规划步骤，打开文件，改代码，跑命令，读报错，再改一轮。

所以判断是不是 AI 编程，不看模型叫什么名字，看它有没有这三样能力：

| 能力 | 含义 |
|---|---|
| 规划 | 把目标拆成可执行步骤，而不是一次吐出整份代码 |
| 工具 | 能读写仓库、跑终端、查文档，而不是只在对话框里说话 |
| 闭环 | 能根据执行结果调整下一步，而不是写完就停 |

缺任何一样，都还在「生成文本帮你写代码」的阶段。有了这三样，才进入「委托一个任务」的阶段。

一个可对照的场景：你要给登录页加「记住我」。补全会在你写到 `localStorage` 时弹出下一行；AI 编程会自己找到登录组件、改状态逻辑、补测试、跑一遍，再把 diff 交回来。你验收的是结果，不是逐行提示。

## AI 编程和代码补全的三个区别

两者用的可能是同一个底层模型，工作契约完全不同。差别集中在三处。

| 对比项 | 代码补全 | AI 编程 |
|---|---|---|
| 作用范围 | 当前光标附近的几行到几十行 | 一个可验收的任务，常跨多个文件 |
| 谁在驱动 | 人打字，模型跟笔 | 人定目标，模型推进步骤 |
| 有没有反馈环 | 基本没有；写错了靠人发现 | 有；能跑测试、读日志、再改 |

**第一，范围。** 补全的上下文窗口事实上被钉在「你正在看的那一块」。AI 编程的上下文是任务相关的文件、规则和命令输出，可以主动去取，也可以被错误地塞满。范围一变大，翻车面也变大——这是后面几篇要反复碰到的主题。

**第二，驱动权。** 补全永远等你先动。AI 编程把「下一步做什么」交给模型。驱动权一交出去，规格和边界就必须写清楚，否则模型会用自己的默认假设填空。

**第三，反馈环。** 补全不知道这段代码能不能跑。Agent 可以执行 `npm test`、读失败信息、改完再跑。闭环让它能自己修一批低级错误，也让它更敢「顺手改一点别的」——检查和验收因此从可选项变成必需品。

一句话收束：补全是加速打字；AI 编程是外包执行。外包执行省的是手速，换来的是你必须更会定目标和验结果。

## 一次 Agent 任务的生命周期：拆解、执行、检查、迭代

把一次成功的 Agent 任务摊开，几乎都落在四步循环上。

**1. 拆解。** 模型先把目标变成步骤清单：要改哪些文件、先读什么、怎么验证。拆得好，后面每一步都短；拆得糊，后面就会一次改十个文件。

**2. 执行。** 按步骤调用工具：读文件、写补丁、跑命令。这一步产出的是仓库里的真实变更，不是聊天记录。

**3. 检查。** 用测试、类型检查、lint，或你在规格里写死的验收条件，判断当前结果过不过关。没有检查标准，就没有「做完」这回事。

**4. 迭代。** 检查失败就回到拆解或执行，带着报错信息改下一轮。成功就停，把 diff 交给人做最终判断。

四步里，人和模型的分工是固定的：

| 步骤 | 模型主要做什么 | 人主要守什么 |
|---|---|---|
| 拆解 | 提议步骤 | 目标、非目标、改动边界 |
| 执行 | 改代码、跑命令 | 敏感操作的授权 |
| 检查 | 跑自动化验收 | 验收标准本身对不对 |
| 迭代 | 根据失败信息再试 | 何时叫停、何时接手 |

生命周期本身不保证质量。它只保证：任务是在「目标 → 证据 → 再决策」的轨道上跑，而不是在对话框里一次性赌对。

## 要点总结：AI 编程的边界在哪

1. AI 编程是 Agent 自主执行可验收任务，核心是规划、工具和闭环，不是更快的自动补全。
2. 和补全的三个区别：作用范围、驱动权、有没有反馈环。
3. 一次任务按拆解 → 执行 → 检查 → 迭代循环；人守目标和验收，模型推进步骤。
4. 边界在这里：写代码的成本在下降，定标准、划边界、担责任仍在人这边。
