# HTML 文档骨架是什么？先写 DOCTYPE

## 1. 基本概述

上一篇你保存了 `index.html`，双击之后，标题和段落都出现了。再看浏览器顶部的标签页，上面多半写着文件名 `index.html`，而不是这页在讲什么。

字能出现，是因为浏览器把你没写的部分补上了。补完能看见正文，不等于这份文件自己把该说的话说完了。这页按哪套规则来读、标签页该叫什么、这些中文按哪种编码来认，上一篇都还没写。

先给一句不用背的回答：**文档骨架就是每页开头固定的那几行，告诉浏览器按现在的规则读这份文件，这页叫什么，正文从哪里开始。**

把它想成一封已经写好的信。信纸上的字，是上一篇那行标题和那段话。骨架是信封：走哪套邮政规矩、信是中文写的、收件箱列表里显示的标题。人读的是信纸，列表里看见的是信封上那一行。信封写错，信纸上的字再对，也会投错格子，或者在列表里只露出一个文件名。

四件事先有个印象：

**漏了也能看见字，不代表骨架写对了。** 浏览器会猜。正文这种它猜得出来，所以页面看起来正常；用哪套规则来排、字节该认成哪个字，猜错了你一时也看不出。

**页面中央的大字，和标签页上的字，是两处。** 改信纸上的标题，收件箱那一行不会跟着变。

**中文能对上，是因为字节被认对了。** 文件里存的是字节。保存文件的方式和开头声明的是同一套，屏幕上才是你打进去的字。

**整页分成外面和里面。** 外面是给浏览器看的说明，里面是给读者看的内容。说明不铺在页面中间。

## 2. 专业定义

上面是直觉。现在把话说准。

**文档骨架是 HTML 页面的最外层结构：`<!DOCTYPE html>` 指定标准模式，`html` 是根，`head` 放文档信息，`body` 放可见内容。**

| 名称 | 准确含义 | 本篇怎么写 |
|---|---|---|
| `<!DOCTYPE html>` | 文档类型声明，不是元素。没有结束标签，页面上也不占一块地方。它要求浏览器按现代 HTML 的标准模式解析 | 放在文件第一行 |
| `html` | 根元素，一页只有一个，包住 `head` 和 `body` | `<html lang="zh-CN">` |
| `head` | 文档信息。这里的内容不铺在页面正文里 | 只放编码和 `title` |
| `body` | 读者在页面上看到的内容 | 放上一篇的标题和段落 |

四个词再拆开，后面写页面会反复用到。

**标准模式和怪异模式。** 有 `<!DOCTYPE html>` 时，浏览器进入标准模式。控制台里 `document.compatMode` 的值是 `CSS1Compat`。这个字符串是历史留下的名字，表示「按标准来」。漏掉第一行，浏览器进入怪异模式，值变成 `BackCompat`，表示「照旧规则兼容」。怪异模式仍会把正文画出来，所以页面看上去没区别。已经变了的是模式：它保留一批旧的排版规则，写 CSS 时才会露出来。有哪些规则，以 WHATWG 的 Quirks Mode 标准为准。样式从模块六才写，模式在打开这一页时就已经定了。

浏览器会补上你没写的 `html`、`head`、`body`。它不会补 `DOCTYPE`。上一篇那个文件能显示，就是补元素，同时停在怪异模式。

**`lang="zh-CN"`。** `lang` 是语言标签，写在 `<html>` 上，遵循 BCP 47。`zh-CN` 表示中国大陆使用的简体中文，中间是连字符。它不翻译页面，也不改变字号和颜色。读屏软件按它决定怎么朗读，浏览器判断要不要提示翻译时会参考它。写成 `zh_CN` 或 `cn`，页面不会报错，只是这句语言标签是无效的。

**`charset`。** `<meta charset="UTF-8">` 告诉浏览器：文件里的字节按 UTF-8 解码成字符。它是空元素，没有结束标签，不要写 `</meta>`。文件本身也要用 UTF-8 保存，两边必须是同一个名字。浏览器只在文件开头这一小段里寻找这条声明（规范里的预扫描上限是 1024 字节），所以把它放在 `head` 的第一行。

现在的 HTML 规范约定，猜不到编码时回退到 UTF-8。我在 Chrome 里打开一份 UTF-8 文件、删掉这行之后，`document.characterSet` 仍是 `UTF-8`，中文照样正常。这是猜对了，不是这行多余。文件编码和声明不一致时，中文会变成另一串字。页面若由服务器发出，响应头里的编码优先于这个 `meta`；本地双击打开没有响应头，这行就是你能写上的依据。

**`title`。** 文档标题，显示在浏览器标签页上，也用作收藏夹里的名称。它不出现在页面正文里。页面上那行大字是 `h1`，两边经常写成同一句话，但它们是两个元素：改 `h1` 不会改标签页。没写 `title` 时，`document.title` 是空字符串，标签页上就没有文档标题，只能看到文件名或地址。搜索结果里怎么采用 `title`，是后面「标题和描述」那一篇的事。

本篇的 `head` 里就这两样。网页图标、给搜索结果准备的描述、`viewport`、样式表，都放在 `head`，但各有各的篇，这里不写。

日常查 `compatMode`、`charset`、`lang`，用 MDN（`developer.mozilla.org`）。对不上时，以 WHATWG 的 HTML Living Standard 为准。

## 3. 代码示例

还用上一篇的 `index.html`。整份换成下面的内容，保存，回到浏览器刷新。Mac 用 `Cmd + R`，Windows 用 `F5`。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>前端从零到架构师</title>
</head>
<body>
  <h1>前端从零到架构师</h1>
  <p>这是一门给零基础的人准备的课程。</p>
</body>
</html>
```

你会看到两处不同的字。页面里是一行大字加一段话，这是 `body`。标签页上变成「前端从零到架构师」，这是 `title`，不再是文件名。

文件仍用 UTF-8 保存。Cursor、VS Code 的右下角会标着 UTF-8。地址栏以 `file:///` 开头，说明还是本地文件。

接着确认骨架真的生效。用 Chrome 或 Edge 打开这个文件，在页面空白处右键，选「检查」（英文界面是 Inspect），点「控制台」（Console）。Mac 也可以直接按 `Option + Command + J`，Windows 按 `Ctrl + Shift + J`。逐行输入下面四句，每句回车一次：

```js
document.compatMode
document.characterSet
document.documentElement.lang
document.title
```

四次结果依次是 `CSS1Compat`、`UTF-8`、`zh-CN`、`前端从零到架构师`。

### 删掉第一行

把 `<!DOCTYPE html>` 那一行删掉，保存，刷新，再输入 `document.compatMode`。

结果变成 `BackCompat`。页面上的标题和段落还在，标签页上的字也还在。怪异模式不会把内容藏起来，它换掉的是排版规则。把第一行加回去，刷新，值回到 `CSS1Compat`。

### 让编码声明和文件不一致

第一行保持不动。把 `charset` 的值改成 `GBK`，再把 `title` 和 `h1` 里的字都暂时改成「你好」，方便对照。不要把文件另存成 GBK，右下角仍应是 UTF-8。保存，刷新。

标签页和页面上的「你好」都会变成「浣犲ソ」。字节没变，浏览器用 GBK 这套码表去认 UTF-8 的字节，就认成了别的字。

改回 `UTF-8`，文字改回「前端从零到架构师」，刷新，显示恢复。后面几篇都从这份完整骨架继续。

`head` 里不要放正文。在 `title` 下面单独加一行「这行字写在 head 里」，不包进任何标签，刷新后它会出现在页面顶部。浏览器一遇到 `head` 里的普通文字，就结束 `head`、开始 `body`，把这行字挪进去。看完把这行字删掉。正文只写在 `body` 里。

## 4. 知识小结

一份页面的骨架，就这几层：

```
index.html
├─ <!DOCTYPE html>     标准模式（页面上看不见）
└─ html lang="zh-CN"   整页，并标明是简体中文
   ├─ head             文档信息，不铺在正文里
   │  ├─ meta charset  按 UTF-8 把字节认成字
   │  └─ title         标签页、收藏夹上的名字
   └─ body             读者在页面上看到的内容
```

| 位置 | 读者在哪感知到 | 漏写或写错时 |
|---|---|---|
| `DOCTYPE` | 控制台里的 `document.compatMode` | 变成 `BackCompat`，正文仍在 |
| `lang` | 读屏和翻译所依据的语言 | 页面不报错，语言标签无效 |
| `charset` | 中文是不是你打的那些字 | 和文件编码不一致时，字会错位 |
| `title` | 标签页、收藏名称 | `document.title` 为空，只剩文件名或地址 |
| `body` | 页面上的字 | 浏览器会补一个，内容仍出现 |

本篇最容易写错的三处：

1. **第一行没写，页面却正常**：标题和段落都在 → 浏览器会补 `html`、`head`、`body`，不会补 `DOCTYPE`，文档进入怪异模式 → 第一行固定写 `<!DOCTYPE html>`，刷新后 `document.compatMode` 应是 `CSS1Compat`。
2. **中文变成了别的字**：你写的「你好」显示成「浣犲ソ」 → 文件是 UTF-8，`charset` 却写成了 GBK，浏览器用错的码表翻译字节。只删掉 `charset`、文件仍是 UTF-8 时，Chrome 里往往仍然正常，那是猜对了 → 文件保存为 UTF-8，`head` 第一行写 `<meta charset="UTF-8">`。
3. **改了页面上的大字，标签页不变**：`h1` 改过了，标签页还是旧标题或文件名 → 标签页读的是 `title`；没写 `title` 时 `document.title` 是空的 → 改 `head` 里的 `<title>`，保存后刷新。`h1` 管页面上的标题，层级规则是下一篇的事。

## 5. 必须掌握

1. 文件第一行写 `<!DOCTYPE html>`。它不是元素，作用是进入标准模式；漏写则是怪异模式，正文仍可能显示。
2. `html` 包住整页，`head` 放文档信息，`body` 放读者在页面上看到的内容。浏览器会补这三个元素，不会补 `DOCTYPE` 和 `title`。
3. `<meta charset="UTF-8">` 放在 `head` 第一行，文件本身也保存为 UTF-8。两边不一致，中文就会错。
4. `<html lang="zh-CN">` 标明这页是简体中文。它不翻译页面，也不管外观。
5. 标签页上的文字来自 `title`。改 `h1` 不会改标签页；没写 `title`，就没有文档标题。
