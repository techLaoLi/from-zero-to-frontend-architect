# 从零基础到前端架构师 · 课程专栏仓库

> 作者：程序小武哥 ｜ 发布平台：CSDN（以专栏形式连载）
> 一套完整的「从零基础到前端架构师」课程体系：**6 个阶段 × 22 个专栏**。篇数以各专栏清单为准；专栏 01 已拆为 101 篇。

## 核心原则

- **一个专栏 = 一次可交付的能力增量**（完整的一块技能沉淀）
- **一篇博客 = 一个知识点**（讲透就停，不贪多）

## 目录约定

1. **阶段目录**：`S{n}-{阶段名}`，一个阶段 = 一次能力层级跃迁。
2. **专栏目录**：`{两位编号}-{专栏名}`，编号全局唯一（01–22），与 CSDN 专栏一一对应。
3. **专栏内 README.md**：记录该专栏的定位、文章清单与写作状态，随写作进度更新 checkbox。拆细时遵守下面的「专栏拆分约定」。
4. **一篇博客 = 一个文件夹**：`{三位序号}-{知识点}/`，如 `001-文档结构/`、`005-闭包的应用与内存泄漏/`。
   - 序号 = CSDN 专栏内的发布顺序；
   - 文件夹名即知识点标题，一篇只讲一个知识点；
   - 文件夹内固定两件：`正文.md`、`主图.png`。正文负责讲清楚，主图用于 CSDN 发布时选封面。

## 专栏拆分约定

专栏 01 是粒度样例。专栏 02 到 22 仍是粗清单；每次拆模块、拆文章都按下面四条做，一次只拆一个专栏。

1. **一篇一个机制。** 一个机制是读者要单独记住、并能单独用一次的一套规则。粗标题如果是一整类技术（如「表单」「Grid」「实战」），就拆开。标题要写出这个机制，不用「（一）（二）（三）」。
2. **每篇附 3–5 条大纲。** 带勾选框的是一篇，下面无勾选的缩进是这篇要讲的事实、规则或边界。超过 5 条，或其中一条自己就是另一套机制，就另开一篇。大纲条目不再单独成篇。
3. **模块按学习顺序排。** 一个模块服务同一项学习任务，并用一句话写明它负责什么、把什么留给后面。专栏内从基础机制排到综合使用。实战放在所用机制都讲完之后，每篇只做一件事；实战里冒出来的新机制，先抽成独立的一篇。
4. **守住专栏边界。** 不把后面专栏的内容提前展开。本专栏不采用、但读者会在旧资料里碰到的做法，可以单独留一篇「只认识」。拆完后，专栏 README 写全清单和实数篇数，`CURRICULUM.md` 只保留模块、篇数和一行范围。

## 单篇文章标准模板

`主图.png`：16:9（1920×1080），纯色或轻渐变底，标题居中放大。画面只放与正文 H1 一致的标题。

`正文.md` 的结构就是这篇大纲。大纲有几条，正文就有几节；节标题用大纲原句，顺序不变。不套「概述 / 定义 / 示例 / 小结 / 必须掌握」这类固定骨架。

每一节只讲这一条：开头就是结论，需要验证时紧跟一个能跑的最小例子。不铺垫，不把同一句话换个说法再说一遍。篇幅跟这条大纲本身走，不设字数。

标题不套「讲清楚 XXX」这类模板句式。按 SEO 起：疑问式、`模块名 — 问题`、或正面陈述三选一，标题里必须带上读者会搜的核心词（标签名、属性名、机制名），12–24 字，不加序号，不用「浅谈 / 深入浅出 / 一文搞懂」。

需要连载衔接时，文末加一行 `> 下一篇：...`，不单独成节。

## 发布节奏

- 每周 10 篇；每个专栏先发 5 篇再正式开栏（避免订阅时内容太少劝退）。
- 同一时间只连载 1 个新专栏 + 维护已完结专栏。
- 写作顺序从最基础开始，按专栏编号 01 → 22 递进，不跳栏、不提前穿插后面的阶段。
