# 从零基础到前端架构师 · 课程专栏仓库

> 作者：程序小武哥 ｜ 发布平台：CSDN（以专栏形式连载）
> 一套完整的「从零基础到前端架构师」课程体系：**6 个阶段 × 22 个专栏**。篇数以各专栏清单为准；专栏 01 已拆为 101 篇。

## 核心原则

- **一个专栏 = 一次可交付的能力增量**（完整的一块技能沉淀）
- **一篇博客 = 一个知识点**（讲透就停，不贪多）

## 课程全景

| 阶段 | 定位 | 专栏 | 核心跃迁 |
|---|---|---|---|
| S0 | 语言与浏览器地基 | 3 个 | 从「会写标签」到「理解程序在浏览器中如何运行」 |
| S1 | 框架与组件化 | 4 个 | 从「操作 DOM」到「用声明式思维构建界面」 |
| S2 | 工程化与质量体系 | 4 个 | 从「单人写页面」到「团队可协作交付」 |
| S3 | 架构设计 | 4 个 | 从「搭应用」到「设计应用的结构与边界」 |
| S4 | 性能与可观测性 | 3 个 | 从「功能正确」到「可度量、可治理」 |
| S5 | 全栈、跨端与架构领导力 | 4 个 | 从「前端专家」到「技术决策者」 |

## 目录约定

1. **阶段目录**：`S{n}-{阶段名}`，一个阶段 = 一次能力层级跃迁。
2. **专栏目录**：`{两位编号}-{专栏名}`，编号全局唯一（01–22），与 CSDN 专栏一一对应。
3. **专栏内 README.md**：记录该专栏的定位、文章清单与写作状态，随写作进度更新 checkbox。
4. **一篇博客 = 一个文件夹**：`{三位序号}-{知识点}/`，如 `001-文档结构/`、`005-闭包的应用与内存泄漏/`。
   - 序号 = CSDN 专栏内的发布顺序；
   - 文件夹名即知识点标题，一篇只讲一个知识点；
   - 文件夹内固定两件：`正文.md`、`主图.png`。正文负责讲清楚，主图用于 CSDN 发布时选封面。

## 单篇文章标准模板

`主图.png`：16:9（1920×1080），纯色或轻渐变底，标题居中放大。画面只放与正文 H1 一致的标题。

`正文.md`：

```markdown
# 标题：讲清楚 XXX

## 1. 先看一个问题（问题指引，100 字内）
## 2. 这个知识点是什么（一句判断句定义 + 类比）
## 3. 代码示例（可直接运行，配注释）
## 4. 三个常见坑（或面试怎么问）
## 5. 一张图小结（正文里的理解图，不能代替主图）
## 6. 必须掌握（3–5 条要记住的话）
## 7. 下一篇预告（钩子式收尾）
```

字数控制：单篇 1500–2500 字。面向初学者，开头要有明确的问题指引和概念描述，结尾用「必须掌握」写清要记住的内容。

## 发布节奏

- 每周 10 篇；每个专栏先发 5 篇再正式开栏（避免订阅时内容太少劝退）。
- 同一时间只连载 1 个新专栏 + 维护已完结专栏。
- 写作顺序从最基础开始，按专栏编号 01 → 22 递进，不跳栏、不提前穿插后面的阶段。
